# Original fixed-size process pool construction and return

2026-10-26. (AI-assisted). Two unchanged original `gkernel.gc` methods now execute
natively on SH-4: `(method new dead-pool)` and `(method return-process dead-pool)`.
This advances a dependency of original process deactivation. It does not complete
deactivation, pool allocation/get-process, kernel boot or game playability.

## Original code and metadata

The existing frontend compiles the original method bodies without copying their
logic into C. Typed GOAL wrappers exercise actual method-table dispatch for pool
creation and return. The native fixture installs the original process/tree
constructors and bounded global object allocator explicitly, then restores its
previous method bindings after the checks.

`make_dead_pool_schema.py` obtains the original kernel header's typed frontend IR.
It reads the single straight-line `type.new` declaration for `dead-pool`, rather
than guessing its layout from a C struct. Original flags are **68,719,476,768**:
32-byte instances, zero heap-base bias and 16 method slots, parent `process-tree`.
The native test cross-checks these with the inherited tree prefix and typed
dispatch. Source/frontend/IR hashes are recorded in its generated manifest.

This is metadata extraction only. The complete kernel-header initializer still
fails lowering on unresolved autogenerated inspection functions. The helper
does not claim to execute that initializer or supply substitute inspect methods.
Unimplemented pool methods remain unimplemented.

## Verified semantics

Stock 16 MiB Flycast passes **22,770 native runtime checks**, including 121 new
pool checks. All **382 host tests** pass, including metadata extraction and strict
missing/duplicate/control-flow refusal. Existing numeric coverage remains 39
checks at its prior verified checkpoint; the numeric lowerer is unchanged.

The new native cases verify empty, one-member and three-member pools. They check
exact aligned allocation footprints, original type/name/mask fields, stable
self handles, complete finite child chains, owning-pool and parent links, dead
status, zero initial PIDs, absent CPU threads and original member heap geometry.

An original `change-parent` call moves a member into an independent tree. Typed
GOAL `return-process` then moves it back to its owning pool without allocating.
A comparison of the complete 368-byte member reservation permits changes only
to the original parent and sibling links. The old tree loses the member; the pool
regains its original sibling chain. Status and PID deliberately remain unchanged:
the original return method does not run exit handlers or perform deactivation.

The two original methods occupy 1,296 and 164 bytes of native code, with optimized
104- and 40-byte stack frames. Total diagnostic GOAL code is 144,114 bytes; arena
use is 660,064 / 1,048,576 bytes with 701 symbols. These figures exclude KOS,
executable/static storage, C contexts/working stacks and rendering. They are not
a whole-game fit or physical hardware performance claim.

## Reproduce

Build the configured original frontend and host tools, then run:

```sh
python ports/dreamcast/build_runtime_goal.py --msys /path/to/msys --verify --output /private/pool-check
```

The builder regenerates the original metadata and method/dispatch modules before
the SH-4 build. `--msys` supplies the Windows runtime DLL/build-shell root for
the frontend and native tools. The metadata helper also accepts an optional
`--runtime-bin` directory when used separately. Only one SH-4 build should run at
a time; the frontend executable must not be relinked while clients execute it.

No game images, converted assets or embedding ELF binaries are published.

## Remaining lifecycle work

Full `(method deactivate process)` still refuses lowering: its lexical r13 `pp`
rebinding, r15 execution-offset role and nonlocal return operations are not
implemented. Allocation binding still does not imply execution identity. Existing
unsupported/resetless/mutable fixed-register roles remain fail-closed.

Original exit callbacks must observe the correct lexical process while scheduler
`*kernel-context*` identity remains distinct. Nested callbacks, retained faults,
PID invalidation, process abandonment and initialization throws require verified
restoration/unwind behavior. Dead-pool-heap relocation, GC, complete startup,
the scheduler, original gameplay, audio, progression and saves remain unfinished.
