# Named locals and real function arguments

2026-10-21. (AI-assisted). The original compiler stores both function arguments
and `(local-vars)` entries in FunctionEnv::params. The old exporter assumed each
entry was an argument, then failed with `parameter has no incoming IR value`.
It could not compile ordinary functions that declared named locals.

The exporter now reads constrained values from the initial IR_ValueReset in
their original order and validates the generated argument-copy prefix. Named
locals are exported separately and retain their ordinary virtual registers.
Argument count/order comes from those entry constraints and copies, rather
than the shared name map or assignments found later in the function body.
Malformed or ambiguous entry layouts fail instead of inventing ABI inputs.

Upstream autogenerated inspect methods have real constrained arguments but no
source-name map. Their argument types are taken from the exact copied RegVal;
generated labels are explicitly marked `name_source: frontend-generated`.
Fixed process/self entries are preserved in `implicit_parameters` and rejected
by SH-4 lowering until that separate ABI is implemented. A normal argument or
local named self does not acquire special behavior solely from its name.

Uninitialized and partially initialized local reads still fail the existing
definite-assignment guard. This fix does not initialize locals implicitly, alter
game bodies, implement behavior/process entry or fix shared early returns.

Eight original-frontend integration tests cover zero/one/eight arguments,
mutation, float locals, method arguments, autogenerated inspect arguments,
fixed process/self metadata, and rejection of uninitialized local reads.
The runtime adds 32 native checks, including GCC stack argument positions,
64-bit values, both assignment branches, float results and typed field methods.
The complete suite reaches **106 host tests and 8,014 native runtime checks**
on Flycast with stock 16 MiB RAM. The separate numeric suite remains 39 checks.

Original find-parent-method now exports two arguments (child-type, method-id)
and the current-method local correctly. Lowering still rejects its separate
early-return pattern. Complete gcommon now exports **66 typed functions**, five
with named locals. This is frontend export coverage, not complete lowering,
linking, initialization or execution of gcommon. Full kernel/game boot is open.

The named-local module adds seven native functions and 1,478 emitted code
bytes. The full diagnostic reports 24,344 bytes, including its retained shift
baseline; arena use is 298,448 / 1,048,576 bytes with 217 symbols. These figures
exclude KOS, executable, stack and renderer and do not establish a game budget.

Reproduce with the original frontend and the documented workspace toolchain:

```powershell
./ports/dreamcast/build_host_windows.ps1
python ports/dreamcast/build_goal_frontend_windows.py
python ports/dreamcast/build_runtime_goal.py --verify
python ports/dreamcast/build_numeric_goal.py --verify
```

The host integration tests require the built frontend. Override its path with
GOAL_IR_FRONTEND; an absent frontend skips those integration tests. Build it
before claiming their coverage. Do not relink the Windows frontend while a
test or compile process is executing that .exe; Windows will lock the file.
