# GOAL / SH-4 execution work

AI-assisted development. This work is incomplete. The existing OpenGOAL
InstructionSet enum still has only x86 and ARM64; no full GOAL SH-4 target is
advertised by the normal compiler.

## Verified native foundation

`sh4_backend.py` emits actual SH-4 instructions and performs branch/literal-pool
fixups and absolute symbol relocations. It does not interpret instructions.
The 142 emitted bytes in its eleven probes pass 17 checks on Flycast with
16 MiB RAM:

- Signed 32-bit arithmetic, forward/backward branches and a factorial loop.
- 64-bit register-pair addition with carry and subtraction with borrow.
- Single-precision parameter/return registers.
- PC-relative literal pools, native loads/stores and absolute data relocation.
- Calls from emitted code into a C function, including PR save/restore.
- Data write-back/instruction-cache synchronization after modifying code.

The host tests independently compare generated bytes with GNU SH-4 assembler.
The calling convention was also checked against GCC 15.1.0 assembly output.

## Initial native ABI

The bootstrap uses GCC's SH-4 little-endian `-m4-single` ABI: 64-bit integer
arguments occupy r4:r5 and r6:r7, results r0:r1. Single-precision arguments use
fr5, fr4, fr7, fr6, fr9, fr8, fr11, fr10, with fr0 as the result. The swapped
register pairs matter for noncommutative functions. Calls preserve PR and the
normal callee-saved registers.
The runtime profile also supports up to six further 64-bit integer arguments
in GCC stack slots, verified against GCC and native incoming/outgoing calls.
KOS `dcache_flush_range` then `icache_flush_range` synchronizes linked code.
These rules apply to the probe and planned bridge; they do not imply that all
existing GOAL calling conventions have been ported.

## Verified typed frontend subset

The optional CMake target `goalc-dreamcast-ir` uses the original GOAL reader,
macro expansion and typechecker and exports typed virtual-register IR before
desktop allocation/code generation. Its selection of x86 for frontend setup
does not emit or execute x86 code. Unsupported operations are explicit records.

`lower_sh4_ir.py` is a strict subset backend for that IR. Initial allocation
keeps virtual values in eight-byte stack slots, using scratch register pairs.
It generates native machine code directly. It currently lacks complete types,
mixed/variadic argument lists, integer division/variable shifts, vectors, process contexts,
game object linking and most runtime bridges. The bounded `--runtime` profile
now connects tagged objects, mutable symbols and native function calls to the
C foundation described in `RUNTIME.md`. Unsupported IR fails explicitly.

The original frontend now builds on Windows/MinGW64. The fixture passes through
reader/macro expansion/typechecking, structured IR export and direct native
lowering. Seven numeric GOAL functions pass sixteen target checks. The original,
unchanged `lerp` form from `goal_src/jak1/engine/math/math.gc` passes six more
cases, including values outside the interpolation interval. Its generated body
is 368 bytes, using a 136-byte stack frame including saved registers.

The combined Flycast target passes **39 checks**: 17 emitter/bridge/cache,
16 synthetic typed GOAL, and six original `lerp` cases, with 16 MiB RAM and
2,730 emitted code bytes. Integer and float GOAL-to-GOAL calls execute through
linked absolute function addresses using the native C ABI. This is a bounded,
immutable numeric module, without normal GOAL object initialization or dynamic
function dispatch.
It does not establish a complete compiler, runtime or gameplay.

Entry parameters and mutable local copies are separate original IR values.
The exporter records their mapping, and the lowerer checks definite assignment
over reachable branches/loops. Noncommutative float subtraction checks argument
ordering; a separate GCC assembly oracle checks all eight float argument slots.
Mixed integer/float argument lists remain rejected pending ABI verification.
The module requires declared dependencies, matching argument counts and a
single immutable function origin for each call. Raw/overwritten function
addresses, mutable globals and unresolved symbols are rejected. Literal-pool
relocations are applied to loaded code followed by cache synchronization.
Calls keep live values in stack slots and preserve the native return chain.
These relocations do not implement the original GOAL object format or symbol
table. Float tests compare actual 32-bit values, recording their bits on error.

On Windows, run `build_goal_frontend_windows.py`, then:

```powershell
python compile_goal_subset.py --frontend ../../../og-host/bin/goalc-dreamcast-ir.exe --function dc-goal-add --function dc-goal-sub --function dc-goal-choose --function dc-goal-factorial --function dc-goal-float --function dc-goal-call --function dc-goal-float-call
python compile_goal_subset.py --frontend ../../../og-host/bin/goalc-dreamcast-ir.exe --source ../../goal_src/jak1/engine/math/math.gc --select-defuns --function lerp --header build/game_leaf.h
python build_dreamcast.py --target jak-dc-goal-leaf.elf
python verify_backend.py ../../../flycast/flycast.exe jak-dc-goal-leaf.elf --nm ../../../dc-sdk/sh-elf/bin/sh-elf-nm.exe --output build/verify-goal-leaf --tests 39
```

These commands assume the documented surrounding workspace layout and run from
`ports/dreamcast`. The source selector retains original GOOS reader forms; it
does not copy, rewrite or transpile their bodies. Dependencies of selected leaf
functions must already be available to the frontend.

## Next integration gates

1. **Passed for the numeric subset:** typed frontend -> IR -> SH-4 execution.
2. **Passed for a bounded scalar slice:** symbols, type headers, tagged
   references, allocation, compiled mutable cells and live function dispatch.
   Explicit scalar top-level startup and direct function-object relocations
   also pass; this does not boot the whole original kernel.
3. Original object-format relocations and normal GOAL dispatch, including
   vector returns, mixed/variadic arguments and broad platform bridge boundaries.
   Eight homogeneous integer/float arguments and small native allocation/type
   bridges now pass, including typed method-pointer calls.
   Immutable numeric modules already support native integer/float calls.
4. Differential tests of real original game leaf functions.
5. Original kernel/process/object initialization and a gameplay slice.

Use `outputs/PORT_PROGRESS.md` in the surrounding workspace for the full-game
completion criteria. Native arithmetic does not establish gameplay feasibility.
